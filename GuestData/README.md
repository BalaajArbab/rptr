# Guest baseline

`guest-baseline.db` is generated by the `GuestAdmin export-baseline` command.
Regenerate it whenever the EF model or curated demo data changes.

```powershell
dotnet run --project Tools/GuestAdmin -- export-baseline --spotify-account-id <spotify-account-id>
dotnet run --project Tools/GuestAdmin -- provision-credential --spotify-account-id <spotify-account-id>
```

The generated database contains the selected demo user, owned playlists,
playlist tags, annotated songs, and snippets. It intentionally excludes Spotify
tokens and feedback.

## Configuration

Generate a credential-encryption key once and store the same value in local user
secrets and Azure App Settings:

```powershell
$key = [Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
dotnet user-secrets set "GuestSessions:CredentialEncryptionKey" $key
dotnet user-secrets set "GuestSessions:EntryCode" "<private-demo-code>"
```

Azure uses the equivalent `GuestSessions__CredentialEncryptionKey` and
`GuestSessions__EntryCode` setting names. Keep the App Service at one instance;
the lease and mutable SQLite snapshot are intentionally process-local.

After the secrets and Mongo connection are configured, export and provision the
selected Spotify account:

```powershell
dotnet run --project Tools/GuestAdmin -- export-baseline --spotify-account-id <spotify-account-id>
dotnet run --project Tools/GuestAdmin -- provision-credential --spotify-account-id <spotify-account-id>
```

Commit the resulting `guest-baseline.db`. Publishing fails when it is absent so
a deployment cannot accidentally ship a nonfunctional guest demo.
